# Customer 360 App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Customer 360 Databricks App (React + FastAPI on Databricks Apps, backed by Lakebase) per `capstone-scaffold/CAPSTONE_TASKS.md` tasks T2–T9, and deploy it as a git-source DABs app.

**Architecture:** FastAPI backend serves a built React SPA and `/api/*` routes. Reads of customer lists/detail come from Lakebase synced tables via the app **service principal** (psycopg3 pool). Cross-table metrics + Genie + the external API run via **OBO** (caller's `X-Forwarded-Access-Token`). Writes (notes, segment overrides) go transactionally into Lakebase staging tables + an audit log as the SP. Forward-ETL (T7) uses **Lakehouse Sync (Pattern B)** to replicate staging → `lb_*_history` SCD2, with a dedup-into-gold job the Reports page triggers.

**Tech Stack:** Backend — FastAPI, uvicorn, psycopg[binary,pool] 3.x, databricks-sdk, pydantic v2, python-dotenv, Python 3.11, uv. Frontend — React 18, Vite 5, TypeScript, TanStack Query v5, React Router v6.

- Gold catalog/schema: `lakebase_capstone_catalog.gold` (NOT the doc default `capstone`)

- OBO scopes are EXACTLY `[sql, dashboards.genie]` — no others (platform rejects them).
- ALL Lakebase access is SP-only (`lakebase_sp()`); there is NO `lakebase_obo()` (Lakebase lacks OBO `postgres` scope).
- Actor email for audit = `X-Forwarded-Email` header.
- Pagination: `page_size` default 25, hard cap 100, reject larger with 422; list responses shape `{items,total,page,page_size}`; never return all 10k rows.
- T8 deploy MUST be a git-source app: commit `app/frontend/dist/`, run cmd `["uvicorn","backend.main:app","--host","0.0.0.0","--port","8000"]`, NO top-level `app/package.json` conflict (package.json lives only in `app/frontend/`).
